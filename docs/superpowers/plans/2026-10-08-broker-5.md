# auth-broker 5.0.0 and auth-broker-cli 3.0.0 — implementation plan

**Goal:** move the broker and its CLI onto the published 6.0.0 auth chain, so
that every guarantee of auth-providers 6.0.0 reaches the broker's consumer and
the CLI's user intact, and whatever 6.0.0 leaves to the consumer the broker
either decides openly or hands up.

**Architecture:** the library keeps one provider per (destination, path) —
the row path (`getProvider`, and the token API without a `provider` option)
and the consumer path (the token API with one) — rebuilt, never changed, when
anything its build read changes, and seeded from the session store only when
the stored versioned binding record equals its own. Session writes go through
auth-providers' `refreshStatePersistence` into one plain queue per destination,
governed by the consumer's `onWriteFailure`; every wait is a waiter of
auth-errors' `sharedAttempt`, carrying results as plain outcomes. The CLI is a
consumer of the broker that states every choice (renewal, write policy,
browser per platform, its own interrupt) in its own code.

**Anchors:** goal `docs/superpowers/2026-10-08-broker-5-goal.md`; spec
`docs/superpowers/specs/2026-10-08-broker-5-design.md` (approved with D1–D23
as written; D19, D21 (iv) and D23 as ruled). Section numbers (§n) and test
names below are the spec's. All work lands in PR #46, one task after another,
each as commits on that PR's branch.

  ^6.0.0`, `@mcp-abap-adt/auth-errors ^2.1.1`, `@mcp-abap-adt/interfaces-auth

  ^1.1.0`; dev `@mcp-abap-adt/auth-stores ^4.0.0`, `@mcp-abap-adt/connection
  ^14.0.0`. auth-broker-cli: `@mcp-abap-adt/auth-broker ^5.0.0`,
  `@mcp-abap-adt/auth-providers ^6.0.0`, `@mcp-abap-adt/auth-stores ^4.0.0`,
  `@mcp-abap-adt/auth-errors ^2.1.1`, `@mcp-abap-adt/interfaces-auth ^7.5.0`,
  `@mcp-abap-adt/interfaces-utils ^1.1.0`, `@xmldom/xmldom ^0.9.12` (the SAML
  metadata parser, the one auth-providers uses); dev `typescript` (the
  source tests' AST reader). No `file:`, `link:` or
  `workspace:` specifier in any `package.json`. The lockfile may keep
  `"link": true` only for the workspace sibling (the CLI → the broker); any
  other `"link": true`, or a third-party resolution not from the registry, is
  a defect. After every install: check the lockfile; `npm ls
  @mcp-abap-adt/auth-errors` and `npm ls @mcp-abap-adt/interfaces-auth` show
  one deduplicated copy each.
- **No built-in timeouts** (H4): no `timeoutMs`, no `AbortSignal.timeout`, no
  `setTimeout` bounding a wait, no retry timer; every wait ends on a result, an
  explicit error or its owner's signal.
- **Nothing goes out that should not** (H2): no secret, server text,
  authorization URL or `state` in a log line, an error, a diagnostic or the
  CLI's output — except the provider's login prompt on stderr (D19). No hash
  of a secret is ever persisted. Nothing on stdout but `help` and
  `--version`.
- **No `instanceof` and no word matching on errors**; read failures with
  `readFailure` / `isAuthProviderFailure`; build failures with auth-errors'
  builders only.
- **No regular expressions on untrusted input** (store values, session
  records, server answers, CLI arguments). The binding record is compared,
  never parsed.
- **Tests:** run with the npm scripts only — `npm test -w
  @mcp-abap-adt/auth-broker`, `npm test -w @mcp-abap-adt/auth-broker-cli`,
  with `-- <file>` / `-t <name>` for one file or case; **never `npx jest`**.
  Before the first `npm test` of a session, confirm
  `packages/auth-broker/tests/test-config.yaml` is absent in the worktree (it
  is today); if it appears, ask the user before running the suite, which then
  reaches real systems.
- **No test starts a real browser or a browser launcher** (`xdg-open`, `open`,
  `rundll32`, PowerShell): browsers are test doubles of `IBrowser`. A test may
  spawn the package's own built bins under `node` (as `check:packed` does).
- **Load-bearing breaks** (spec §13 **[break]**): before the break, copy the
  file to the scratch directory; make the break; run the one test and see it
  red; restore the file by copying it back; run it green. Never `git
  checkout` / `git restore` a file to revert.
- **Gates of every task** (from the repository root): `npm run build`, `npm
  run test:check`, `npm run lint:check`, `npm run check:graph`, the task's
  package tests (`npm test -w …`), and from Task 1 on `npm run check:shape`.
  `npm run check` (which adds `check:packed`, needing the registry, and
  `check:publish`) runs at the end of Tasks 13 and 16. Each task ends with its
  commits pushed to PR #46.
- Assertions on a released socket bind the port; assertions are never on a log
  line where a port, a write or a file can be checked instead. A rejection
  expectation is attached before the rejection is triggered.

## Review focus

The five input classes most likely to bite, and the task that pins each:

1. **A session written under other means or by another provider** — a stored
   binding of 4.x format, of another row, client, endpoint or trust, a
   refresh token a replaced provider left behind (Tasks 3, 4, 5).
2. **A store that rejects a write** — a discard rejected while another call
   is in flight, a failed write followed by a newer one, `'fail'` vs
   `'continue'` (Task 6).
3. **A caller that aborts** — while a build reads a store, while a login runs
   in `rejected()`, while its write is queued, with other callers still
   waiting (Task 7).
4. **A failure from another installed copy of auth-errors, or a thrown value
   that is not one** — a store's own error, a strategy's throw, a consumer
   provider answering no token (Task 1, Task 7's slot outcomes).
5. **A user's terminal** — `SIGINT` / `SIGTERM` to the process alone (Task
   12), a platform without a launcher (Task 1), a manual SAML login without
   an ACS (Task 11), output that must not reach stdout (Task 10).

## Found while planning

1. **The source test vs the structural guard.** §13.1 forbids reading
   `.name` / `.message` of a caught value in `src`, but
   `isDestinationConfigError` reads an own data `name` (§3.2) and the CLI
   prints a `DestinationConfigError`'s `message` (§10.9). The plan scopes the
   source test: those reads are allowed only inside `isDestinationConfigError`
   and on a value that guard accepted.
2. **"No test starts a real program" vs §13.2.** The signal tests spawn the
   CLI's own built bin under `node` and signal its PID (a signal to the Jest
   process itself would end the run). The plan allows spawning the package's
   own bin under `node` (as `check:packed` already does) and
   forbids every browser and launcher.
3. **Release order inside one PR.** Releasing the broker, then switching the
   CLI's dependency "from the workspace" to the published 5.0.0 would need a
   second PR after the broker is on the registry. The CLI declares the semver
   range `^5.0.0` throughout (the workspace link is development-only); both
   versions are tagged on PR #46's merge commit, and `release:publish`
   publishes the broker first, then the CLI — the "package of the same
   release published first" case of the standing rule. If the user wants the
   CLI tagged only after the broker is verified on the registry, Task 16
   splits at the tag step, still from the same merge commit.
4. **§13.1 places the CLI's `--cookie` case among the library's tests.** The
   plan tests it in Task 11 (the CLI writes that session).
5. **§13.1's break "build a retry from the single result instead of the latest
   submission"** uses the removed revision model's word; the plan states it as
   "a retry built from an older write instead of the latest" (Task 6).
6. **D23 removes the retry timer,** so a failed write with no later write
   lands only through `flush()`; the goal's "not lost while the process
   lives" holds (it stays pending in memory), and the migration note tells a
   consumer to call `flush()` on shutdown (Task 13).
